# Crash-durable pinned reading (R22 candidate)

Reuse: **REUSE** WizOffline's `wisdom-offline-v1` database, existing `meta` and ordered `outbox` stores; the host presentation facade and app-owned reader fractions; existing inline My Library failure hook. **EXTEND** `WizOffline.presentation`, host hydration/mount ordering, Wisdom's strict-durability opt-in. **NEW:** no database/store, no UI framework, no test-only production API.

## Actual cause
R21 read the killed profile's complete CRC-validated localStorage WAL **before relaunch**. The highlight case retained the collection route and fraction `0.07142857142857142`, while three stable pre-kill frames held the reader route and `0.2857142857142857`. The untouched control retained the latest reader state. Synchronous localStorage readback did not prove a disk commit. Session restoration/copy lock trouble was separate, not an explanation for the already stale disk rows.

## Protocol
- `WizOffline.presentation({prefix:'wisdom-',slot:<origin/app slot>})` uses the existing replica's `meta` key `presentation:<slot>`. The single record is `{v:1,revision,route,positions}`. Fractions are numeric doubles, never rounded server percentages. The last 80 positions are retained, matching bounded presentation storage; updating a position refreshes its retention order.
- The host loads that record before creating any child iframe. A missing record alone permits localStorage migration. An existing journal always wins, including absent positions or a null root route. A mount-generation guard prevents a late readiness callback mounting an obsolete child.
- Page and route writes paint synchronously and keep localStorage as an immediate cache. Each change captures the complete next route/position snapshot and is serialized through an awaited IDB `readwrite` transaction with `{durability:'strict'}`. Completion means `transaction.oncomplete`, not request success. The transaction checks persisted revision before putting; stale concurrent sessions abort instead of overwriting a newer record. No completion callback patches current in-memory state backwards.
- Strict support is checked via the actual transaction's `durability`. Unsupported, blocked, aborted or unavailable storage latches a failure; there is no weaker transaction mislabeled durable. Reading remains available with best-effort cache fallback on hydration failure. Commit failures use the existing quiet My Library failure panel, never a popup or toast.
- Wisdom opts existing outbox/replica readwrite transactions into the same strict helper. Other apps retain the default existing behavior. Highlights and progress still use the existing ordered/idempotent outbox; this adds neither a second queue nor another storage backend.
- The host's generic reading-position service is deliberately unchanged; Wisdom's paginated position override remains app-owned. Normal desk positions, app content/preferences, other apps and native bridge capabilities retain their current contracts.

## Proof boundary
The source-level old/new unit runs prove stale-cache precedence, atomic snapshots, true readiness ordering, revisions, rollback, strict-support rejection, scoped facade behavior and non-Wisdom isolation. They do not prove Chromium fsync or Android rendering.

The parent-only R22 packet repeats the original trusted-touch highlight and untouched-control flow on exact old and candidate sources, unchanged three-frame timing, actual hard process-group death, pre-relaunch disk snapshot and actual UI restoration. No profile is seeded with expected values, no direct book-open surrogate, no copied profile browser launch. Four source/case identities are mandatory. An old failure must be the captured collection-route regression, not arbitrary failure; candidate requires route, exact fraction, full count/sentinel, visible offsets/body/highlights and projected progress equality.

No live-parity/native/image/package/release pass is asserted by staging. Native R19 `5/13` versus `5/15` remains unresolved even if the first page number is equal. No font candidate is included.
